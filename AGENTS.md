## Worked solutions

- Keep the bilingual `guide` brief: concepts, actual givens, goals and starting approach, with the verified lecture-page links. Keep it separate from the original question; do not repeat the full derivation or present computed results as givens.
- Write solutions as worked examples, in this order: “使用以下 crib sheet 公式” → “已知 …，求 …” → “把 … 代入 …” → “得”. Author both languages, with each short lead-in before its displayed calculation. Name the actual quantities and substitutions; do not add generic step titles, repeat the question, or explain routine algebra in paragraphs. “Short” applies to the prose, never to omitting mathematical working. This is a writing flow, not four mandatory UI sections or a fixed number of steps.
- Start with the displayed governing formula. Cite its verified source through the formula name naturally mentioned in the preceding paragraph, using an inline Markdown link such as `[高斯定律](formula:gauss)` in both languages. Use the existing native Hover Card for the original excerpt and retain click-to-locate PDF navigation; links inherit the paragraph’s typography, without an icon or a separate tag beside the equation. Use the crib sheet original when available. Identify a question-supplied definition or an earlier derived result by its actual origin; never label it as a crib formula. Establish new derived relations through their calculations.
- Expand evaluated integrals for a beginner: substitute the actual field/density and differential element, evaluate the dot product, identify and extract factors constant with respect to the integration variable, show the antiderivative, then substitute upper limit minus lower limit before simplifying. Evaluate multiple integrals one variable at a time; do not jump straight to an area/volume factor or final value. Show negative lower limits explicitly as subtraction of a negative. Briefly explain where an unfamiliar area/volume element comes from (for example, cylindrical side area is arc length $R\,d\phi$ times height $dz$), next to its first use.
- Group intermediate algebra and calculus in aligned equations, splitting long derivations at meaningful stages with a short lead-in. Keep the terms of one sum or difference on the same row when they fit at normal reading size; put the subsequent simplification on the next aligned row when useful. Detailed working does not mean putting each operand on a separate line. Keep integration elements, limits, boundary constants, upright units, vector directions and coordinate/sign conventions. A clearly identified result already worked out in an earlier part can be reused. Respect the requested task: a drawing, integral setup or conceptual proof does not require an unrelated full integration.
- Use `\because` and `\therefore` only for a meaningful condition and deduction, not as decoration before every formula. Give them their own right-aligned column and align calculation continuations at their equals signs. Keep short parallel conditions together when they fit; do not force every condition onto one row. On narrow screens, preserve readable math sizing and confine horizontal scrolling to the formula.
- Put results in the final derivation step with only KaTeX boxed emphasis; do not add an answer card, outer border or final-answer heading.
- Verify givens, conventions and results against the official PDFs; inspect page images when handwriting is absent from extracted text. An abbreviated official solution is not a reason to skip intermediate working. Preserve source-correction notes explicitly. For the F26 matching-interface question, select a, b and c: local interface reflection coexists with zero net feedline reflection.

## Figures and provenance

- Source page numbers are 1-based PDF pages. Preserve the PDF copies and SHA-256 provenance. All citation rectangles must fit inside the page and match the cited expression.
- Question and solution figures stay static SVG. Preserve each original perspective, topology, axis, label and given/unknown quantity: retain a 3D source's perspective in the static drawing, without an interactive 3D viewer. Keep both color themes and the original-image switch. Keep solution plots and annotations in revealed solutions, not in question figures.
- Gaussian-surface solution diagrams use $R$ for the fixed surface radius and separate dummy integration coordinates. Draw the problem's actual boundary radii (such as $a$ and $b$ when present) and $R$ from the same center to their own boundaries; do not invent a second boundary in a single-sphere problem. Show the outward normal and enclosed charge, and distinguish volume density from surface density. The spherical diagram uses a shared orthographic projection: far equator behind the inner ball, near equator in front, radii ending on their spherical silhouettes.
- Draw one paper with `python3 content/exam1_f26/generate_figures.py`, or all papers with `python3 scripts/generate_figures.py`. Each paper's renderer owns its drawing configuration; `scripts/plotting.py` and `scripts/question_primitives.py` provide shared Matplotlib/SVG primitives. Source crops use that paper's `figure-sources.json`. In the content pipeline, Python is for offline drawings, PDF image assets and their verification; it never authors or compiles the question bank. Shared formulas and lecture provenance live in `content/formulas.json` and `content/documents.json`; paper PDF provenance stays in its own `documents.json`.
- Figure labels use large, bold text including math symbols, clear of arrows and strokes. Keep the source-exam action in a reserved lower-left figure area in both views; switching figures must preserve the drawing height. Omit boilerplate recreation captions.

## Study interface and saved state

- Titles, statements and subparts follow the global language: Chinese directly translates the original exam text; English shows that original text. Do not add a separate translation switch, supplemental translation panel, or duplicate bilingual question blocks. Navigate questions in the sidebar; do not restore the bottom pager.
- Keep one solution view, without study/practice mode selectors or mode-dependent content. Each part reveals its full worked solution. Use one global solution toggle: if any part is open, collapse all; if none is open, reveal all. Its label and state must follow individual accordion changes as well. Practice is done on paper; do not restore per-part attempt textareas, a notes tab, note-taking inputs or note export controls.
- Preserve existing stored records during feature removals. Retired mode preferences, saved step counts and legacy notes remain compatibility data only; they must not control the current solution view or restore removed inputs. Unplugged papers' stored progress must survive and must not count toward active-paper progress.
- The source viewer's pagination buttons, page input and zoom buttons use consistent native 36 px controls. When width and height allow, show all PDF pages as a vertical, independently scrolling thumbnail list. Clicking a thumbnail changes pages; highlight and automatically reveal the selected page when the toolbar changes it. Preserve the citation marker on its original thumbnail and the visible-region marker on the current page; clicking or using arrow keys on the current thumbnail navigates within the main page. On small screens, preserve the reading area and hide the overview.
- Keep independent navigation and reference sidebar toggles in the top bar, using native shadcn buttons and tooltips. Collapsed panels release reading width and are inert; preserve their internal tab/accordion state and save desktop preferences. On compact screens, the same controls open the existing navigation/reference Sheets without changing desktop preferences. Keep focus outside collapsed panels and respect reduced motion.
