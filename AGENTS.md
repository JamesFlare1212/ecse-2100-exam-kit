# Working on Fieldnotes

## Stack and authored content

- Read `.agents/skills/shadcn-svelte/SKILL.md` and `.agents/skills/ui-ux-pro-max/SKILL.md` before UI changes. Use `design-system/fieldnotes/pages/study.md` for this workspace.
- Use Bun and the installed native shadcn-svelte components. Use Svelte 5 runes and the `#lib` aliases from `components.json`.
- Read `docs/template-guide.md` for course/exam migrations and `docs/solution-style.md` before authoring or reviewing solutions. The latter is the canonical worked-solution style, including bilingual examples and the content-review checklist; do not maintain competing copies of the rules here or in page specs. Course identity, storage namespace, default problem and resource navigation belong in `content/course.json`, not in Svelte components. When `course.id` is `ecse-2100`, also read `docs/courses/ecse-2100.md` for its source corrections and scientific conventions. Copyable examples in `templates/` must stay outside the active content trees.
- Astro discovers matching papers in `content/en/exam{number}_{f|s}{year}/` and `content/zh-cn/exam{number}_{f|s}{year}/`, and questions through its content collection. Each language owns metadata-only `paper.json`, one single-language article per problem in `questions/q{number}.md`, `documents.json`, `figure-sources.json`, its own complete `assets/`, `extracted/` and `generate_figures.py`. Keep both languages' PDFs and images as separate files, even when identical; do not replace either copy with a cross-language fallback or symlink. Markdown is the only authored question-bank source. Do not put English/Chinese language sections or bilingual text objects inside a language article. Pair questions and parts by stable IDs; scores, physical givens and source metadata must agree. Each language owns its complete guide and solution Markdown, with independent paragraphs, equations, formula references and correction prose. Both solutions must remain complete and scientifically consistent; their equation count and layout need not match. Edit Markdown directly; `bun run build` stages local assets, validates and prerenders with Astro and TypeScript, without generated question-bank JSON. Never paraphrase original questions, silently correct their givens, replace worked parts with placeholders, or remove source-correction notes.
- Follow `content/README.md` for the small structural contract: `## Question`, `## Guide`, `## Part {label}` with the prompt directly beneath it, and `### Solution` with ordinary paragraphs and displayed math. Optional source-correction headings retain their notes. Do not restore `Step`, `Explanation`, `Equation` or `Answer` wrappers. Keep frontmatter to metadata and overrides: infer the question number and default figure from the stable ID, resolve original crops from `figure-sources.json`, and key part overrides by printed label. Preserve exceptional stored part IDs explicitly. Astro and the CLI share `content/metadata.ts`; Python only resolves offline asset references.
- Keep each language's canonical paper assets inside its own `assets/` folder. `/static/papers/{en|zh-cn}/` is an ignored staging area, copied automatically for development and builds; never edit it or keep paper resources in root static folders. Language switching must select the corresponding figures, original crops and PDF pages. Discover paper pairs and derive navigation/counts from data, without hardcoded registration; a translated pair counts as one paper. Add or unplug both language folders together.
- Astro owns static routes and the persistent Svelte study island owns the connected interactions; use `astro:transitions/client` for navigation. Each page must carry only its own full problem plus the solution-free navigation index. Keep existing `/problems/{id}/` URLs and stored IDs. Keep runtime assets local and localStorage versioned. Course PDFs may be published with the static site; the restriction is on committing new large PDF binaries to Git, not on site publication. Provision large PDFs in their canonical local asset directories before building, retaining both language copies and SHA-256 provenance. Do not remove existing PDFs, change their tracking status, rewrite Git history or add remote services as part of routine edits.

## Worked solutions

- Follow `docs/solution-style.md` and its review checklist. The invariant is governing formula → actual givens and goal → explicit substitution and complete working → a final boxed calculation, with short prose before equations rather than numbered step wrappers.
- Cite the actual origin of each governing relation; never mislabel a question definition or an earlier derived result as a formula-sheet original. Each language owns a complete independent guide and worked solution, including all needed calculus, conventions and corrections.
- Render the authored Markdown directly. Do not synthesize, deduplicate or append answers; boxed emphasis belongs only in the last displayed calculation. Keep formula links native and inline, and confine overflow to the formula without shrinking the page.
- Human review of scientific correctness, source PDFs and translation is mandatory. Automated structure/TeX checks and passing style examples are not proof that an arbitrary new worked solution is correct.

## Figures and provenance

- Source page numbers are 1-based PDF pages. Preserve the PDF copies and SHA-256 provenance. All citation rectangles must fit inside the page and match the cited expression.
- Question and solution figures stay static SVG. Preserve each original perspective, topology, axis, label and given/unknown quantity: retain a 3D source's perspective in the static drawing, without an interactive 3D viewer. Keep both color themes and the original-image switch. Keep solution plots and annotations in revealed solutions, not in question figures.
- Scientific geometry and notation constraints belong to the course profile and paper-local renderer; preserve those conventions when editing that course. For the shipped ECSE 2100 course, Gaussian-surface and sphere-projection invariants remain in `docs/courses/ecse-2100.md`, not as requirements imposed on unrelated subjects.
- Draw one language's paper with `python3 content/en/exam1_f26/generate_figures.py` (or `content/zh-cn/...`), or both languages with `python3 scripts/generate_figures.py`. Use `--locale en` or `--locale zh-cn` to limit the batch. Each paper's renderer owns its drawing configuration; `scripts/plotting.py` and `scripts/question_primitives.py` provide shared Matplotlib/SVG primitives. Source crops use that language's `figure-sources.json`. In the content pipeline, Python is for offline drawings, PDF image assets and their verification; it never authors or compiles the question bank. Shared formulas and lecture provenance remain in `content/formulas.json` and `content/documents.json`; each language's paper PDF provenance stays in its own `documents.json`.
- Figure labels use large, bold text including math symbols, clear of arrows and strokes. Keep the source-exam action in a reserved lower-left figure area in both views; switching figures must preserve the drawing height. Omit boilerplate recreation captions.

## Study interface and saved state

- Titles, statements and subparts follow the global language: Chinese directly translates the original exam text; English shows that original text. Do not add a separate translation switch, supplemental translation panel, or duplicate bilingual question blocks. Navigate questions in the sidebar; do not restore the bottom pager.
- Keep one solution view, without study/practice mode selectors or mode-dependent content. Each part reveals its full worked solution. Use one global solution toggle: if any part is open, collapse all; if none is open, reveal all. Its label and state must follow individual accordion changes as well. Practice is done on paper; do not restore per-part attempt textareas, a notes tab, note-taking inputs or note export controls.
- Preserve existing stored records during feature removals. Retired mode preferences, saved step counts and legacy notes remain compatibility data only; they must not control the current solution view or restore removed inputs. Unplugged papers' stored progress must survive and must not count toward active-paper progress.
- The source viewer's pagination buttons, page input and zoom buttons use consistent native 36 px controls. When width and height allow, show all PDF pages as a vertical, independently scrolling thumbnail list. Clicking a thumbnail changes pages; highlight and automatically reveal the selected page when the toolbar changes it. Preserve the citation marker on its original thumbnail and the visible-region marker on the current page; clicking or using arrow keys on the current thumbnail navigates within the main page. On small screens, preserve the reading area and hide the overview.
- Keep independent navigation and reference sidebar toggles in the top bar, using native shadcn buttons and tooltips. Collapsed panels release reading width and are inert; preserve their internal tab/accordion state and save desktop preferences. On compact screens, the same controls open the existing navigation/reference Sheets without changing desktop preferences. Keep focus outside collapsed panels and respect reduced motion.

## Verification

- Run `bun run check`, `bun test`, and `bun run build` for substantive changes. Exercise the affected UI in the browser at desktop and phone widths.
- After scientific figure changes, run `python3 scripts/check_figures.py` in the Matplotlib environment. It checks both themes, Matplotlib-stage label collisions and spherical radius/normal geometry, plus delivered SVG font coverage and budgets, without rewriting static assets. Its collision checks precede Chinese SVG label replacement; visually inspect the final localized SVGs as well.
