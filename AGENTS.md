# Working on Fieldnotes

- Read `.agents/skills/shadcn-svelte/SKILL.md` and `.agents/skills/ui-ux-pro-max/SKILL.md` before UI changes. Use `design-system/fieldnotes/pages/study.md` for this workspace.
- Use Bun and the installed native shadcn-svelte components. Use Svelte 5 runes and the `#lib` aliases from `components.json`.
- Astro discovers papers in `content/exam{number}_{f|s}{year}/`, for example `content/exam1_f26/`, and questions through its content collection. Each paper owns metadata-only `paper.json`, one article per problem in `questions/q{number}.md`, `documents.json`, `figure-sources.json`, `assets/`, `extracted/` and `generate_figures.py`. Markdown is the only authored question-bank source: YAML frontmatter holds stable IDs, scores and source/figure metadata; the body holds exact English wording, faithful Chinese translations, guides, full worked steps and source-correction notes. Follow `content/README.md` for its heading convention. Edit Markdown directly; `bun run build` stages local assets, validates and prerenders with Astro and TypeScript, without generated question-bank JSON. Never paraphrase the original questions, silently correct their givens, replace worked parts with placeholders, or remove a source-correction note.
- Keep the bilingual `guide` brief: concepts, actual givens, goals and starting approach, with the verified lecture-page links. Keep it separate from the original question; do not repeat the full derivation or present computed results as givens.
- Write solutions as short worked examples, in this order: “使用以下 crib sheet 公式” → “已知 …，求 …” → “把 … 代入 …” → “得”. Author both languages, with each short lead-in before its displayed calculation. Name the actual quantities and substitutions; do not add generic step titles, repeat the question, or explain routine algebra in paragraphs. This is a writing flow, not four mandatory UI sections or a fixed number of steps.
- Start with the displayed governing formula and put its existing verified source link beside it. Use the crib sheet original when available. Identify a question-supplied definition or an earlier derived result by its actual origin; never label it as a crib formula. Explain a derived relation through the calculation that establishes it. Use `\because` and `\therefore` only for a meaningful condition and deduction, not as decoration before every formula.
- Group substitutions and intermediate algebra or calculus in aligned equations. Keep necessary integration elements, limits, antiderivatives, boundary constants, upright units, vector directions and coordinate/sign conventions. Preserve complete reasoning and source-correction notes while removing repetitive narration and duplicate equations. Check against the official PDFs; inspect page images when handwriting is absent from extracted text.
- Gaussian-surface solution diagrams use R for the fixed surface radius and separate dummy integration coordinates. Draw a, b and R from the same center to their own boundaries, show the outward normal and the enclosed charge, and distinguish volume density from surface density. Preserve source corrections explicitly. For the F26 matching-interface question, select a, b and c: local interface reflection coexists with zero net feedline reflection.
- Source page numbers are 1-based PDF pages. Preserve the PDF copies and SHA-256 provenance. All citation rectangles must fit inside the page and match the cited expression.
- Question and solution figures stay static SVG; preserve the original-image switch. The spherical diagram uses a shared orthographic projection: far equator behind the inner ball, near equator in front, radii ending on their spherical silhouettes. Do not add an interactive 3D viewer.
- Draw one paper with `python3 content/exam1_f26/generate_figures.py`, or all papers with `python3 scripts/generate_figures.py`. Each paper's renderer owns its drawing configuration; `scripts/plotting.py` and `scripts/question_primitives.py` provide shared Matplotlib/SVG primitives. Source crops use that paper's `figure-sources.json`. Python is only for offline drawings, PDF image assets and their verification; it never authors or compiles the question bank. Shared formulas and lecture provenance live in `content/formulas.json` and `content/documents.json`; paper PDF provenance stays in its own `documents.json`. Preserve each original perspective, topology, axis, label and given/unknown quantity: a 3D source must retain its 3D view. Keep solution plots and annotations in revealed solutions, not in question figures. Keep both color themes and the original figure switch.
- Keep canonical paper assets inside its `assets/` folder. `/static/papers/` is an ignored staging area, copied automatically for development and builds; never edit it or keep duplicate paper resources in root static folders. Discover papers and derive navigation/counts from data, without hardcoded registration. Unplugged papers' stored progress must survive and must not count toward active-paper progress.
- Figure labels use large, bold text including math symbols, clear of arrows and strokes. Keep the source-exam action in a reserved lower-left figure area in both views; switching figures must preserve the drawing height. Omit boilerplate recreation captions. Results belong in the final derivation step and use only KaTeX boxed emphasis; do not add an answer card, outer border or final-answer heading. Navigate questions in the sidebar; do not restore the bottom pager.
- Titles, statements and subparts follow the global language: Chinese directly translates the original exam text; English shows that original text. Do not add a separate translation switch, supplemental translation panel, or duplicate bilingual question blocks. Keep one solution view, without study/practice mode selectors or mode-dependent content. Preserve retired mode preferences as compatibility data only. Practice is done on paper; do not restore the per-part attempt textarea. Use one global solution toggle: if any part is open, collapse all; if none is open, reveal all. Its label and state must follow individual accordion changes as well.
- The source viewer uses consistent native 36 px controls. When width and height allow, show all PDF pages as a vertical, independently scrolling thumbnail list. Clicking a thumbnail changes pages; highlight and automatically reveal the selected page when the toolbar changes it. Preserve the citation marker on its original thumbnail and the visible-region marker on the current page; clicking or using arrow keys on the current thumbnail navigates within the main page. On small screens, preserve the reading area and hide the overview.
- Keep independent navigation and reference sidebar toggles in the top bar, using native shadcn buttons and tooltips. Collapsed panels release reading width and are inert; preserve their internal tab/accordion state and save desktop preferences. On compact screens, the same controls open the existing navigation/reference Sheets without changing desktop preferences. Keep focus outside collapsed panels and respect reduced motion.
- Keep runtime assets local and localStorage versioned. Astro owns static routes and the persistent Svelte study island owns the connected interactions; use `astro:transitions/client` for navigation. Each page must carry only its own full problem plus the solution-free navigation index. Keep existing `/problems/{id}/` URLs and stored IDs. Do not add a notes tab, note-taking inputs, or note export controls; practice is done on paper. Preserve existing stored records during feature removals. Do not publish course PDFs or add remote services as part of routine edits.
- Run `bun run check`, `bun test`, and `bun run build` for substantive changes. Exercise the affected UI in the browser at desktop and phone widths.
- After scientific figure changes, run `python3 scripts/check_figures.py` in the Matplotlib environment. It checks both themes, label collisions and spherical radius/normal geometry without rewriting static assets.
